## 1. 个人总结与技能（常考概念）

### Q1.1 你怎么理解「微服务拆分」？结合你做过的系统说

**答点：**  
- 按业务能力拆（承保、批改、理赔；线索、BDC、外呼、活动），不是按技术层硬切。  
- 拆完必须配：网关鉴权路由、注册发现、熔断降级、调用链与一致性方案。  
- 简历锚点：车险核心承保微服务；4S BDC 多服务；增值服务订单/库存拆分。

### Q1.2 分布式事务你怎么做的？为什么不用强一致 Twophase？

**答点（简历口径）：**  
- 常用 **RocketMQ 可靠消息 + 最大努力通知**，做最终一致性。  
- 场景：增值服务「下单 + 扣库存」跨服务；车险核心微服务间解耦与削峰。  
- 选型理由：保险/交易链路更吃可用性与削峰，强一致成本高、耦合重；业务可接受短暂不一致 + 补偿/对账。

**追问准备：** 本地消息表 vs 事务消息；重复消费幂等；对账与补偿。

### Q1.3 分库分表与数据迁移，你怎么保证不停机或少停机？

**答点：**  
- 大搜车 V1 单库 → V2 分库：冷数据代码少量多次迁；近三个月热数据停服 + DBA 迁，平衡时间与影响。  
- 通用迁移平台：全量（分阶段、可中断、断点续传）+ 增量（Canal → MQ → 新库）+ 校验与进度。  
- 增量丢消息风险：手动拉取/提交 + 消息记录表状态机，避免「丢了就永远不一致」。

### Q1.4 Canal + MQ 做 MySQL / Redis / ES 一致性，讲一下链路

**答点：**  
MySQL binlog → Canal → RocketMQ → 消费更新 Redis / ES。  
目的：列表检索与缓存读路径和主库近实时一致；导出等重操作走 MQ + OSS，保护核心跟进链路。

### Q1.5 消息积压、重复消费、顺序消息怎么处理？

结合 MQ 削峰经验答：扩容消费者、拆 Topic/Tag、限流与降级；幂等键（业务单号）；顺序场景用队列选择键或单分区业务键。没有简历数字就别编 QPS，讲机制。

### Q1.6 JVM / SQL / 接口性能优化你怎么排查？

**答点：**  
- 链路：ARMS / 日志 / 慢 SQL / 线程栈。  
- SQL：索引、分页、避免大结果集；分库后路由键。  
- JVM：GC 日志、堆与元空间、泄漏与大对象。  
- 接口：缓存热点、异步化导出、限流熔断。  
简历技能写了 ACK / ARMS / DAS，可点到「用过云监控与诊断」，有案例再展开。

### Q1.7 DDD 你怎么落到项目里的？

锚点：AI 全链路效能平台后端 DDD 分层；强调边界（领域模型 vs 基础设施），别背教科书。说明如何避免「伪 DDD 包结构」。

## 2. 京东 · AI Coding Agent 编排工作台（hb-cli / agent-desk）

### Q2.1 用一分钟讲这个项目

本地优先的 Coding Agent 编排工作台：安装 CLI/技能 → 拉缺陷 → 编排任务/工作流 → 多 Agent（JoyCode/Claude/Codex/Cursor）本地执行 → **人工卡点** → 飞书/钉钉深链继续或中止 → 归档。  
内网 hb-cli 对接 Hiboos/JoyCode；开源同源 agent-desk。

### Q2.2 为什么要「本地优先」而不是全上云 Agent？

- 代码与密钥默认留本机，可观测、可中断。  
- 各家 CLI 差异大，适合在开发者环境做 harness。  
- 分发层（Artifactory）只管安装包与技能版本，不把会话黑盒搬上集群。

### Q2.3 人工卡点怎么设计的？

- Agent 输出解析 `oh-choices` → 任务进入 `awaiting`。  
- Webhook / 飞书 / 钉钉深链回复继续或 abort。  
- 目标：「Agent 提议、人来批准」，避免无人值守误改。

### Q2.4 任务状态机有哪些状态？执行器和控制面怎么拆？

- 生命周期：created → queued → running → awaiting → done / failed / stopped。  
- 控制面：API、状态、Webhook；执行器：子进程、停止/续跑、孤儿回收、stdout/stderr 时间轴。

### Q2.5 多 Agent CLI 差异你怎么收口？

统一 **Agent Provider**：启动参数、鉴权、输出流、技能挂载差异内聚在适配层；上层只认任务状态与日志回放。

### Q2.6 内外网怎么避免两套产品分叉？

- Schema 优先：任务/工作流/设置可交换。  
- Provider 接口稳定；内网留 JoyCode/缺陷适配，开源 TS monorepo 同源。  
- Skill 种子脚本同步。

### Q2.7 你在其中的角色？

独立完成产品定位、架构与全栈落地（CLI、面板、状态机、执行器、技能、工作流、Provider、通知、发布升级与开源仓）。

**追问：** Skill 包结构、工作流共享会话 vs 并行、如何防 Prompt 注入/误删仓库——按你真实实现答，没有就说约束边界（工作目录、人工卡点、abort）。

## 3. 京东 · AI 全链路研发效能平台

### Q3.1 项目解决什么问题？

### Q3.2 代码图谱怎么建？难点是什么？

- 难点：海量关系与多语言/编译产物；措施：自研，语法树 + 类加载等分析接口与关系（与 API 扫描思路一脉）。

- **hb-cli**：偏「本地 Agent 编排 + 缺陷闭环 + 人工卡点」harness。  
一个偏平台流水线，一个偏开发者侧 Agent 控制系统。

## 5. 大搜车 · 分布式数据迁移与一致性保障平台

### Q5.1 为什么做通用迁移服务？

微服务改造 + 分库后，多系统都要新老同步；从「DBA 个案迁移」升级为内部通用能力。

### Q5.2 全量 / 增量分别怎么做？

- 全量：分阶段批次、可中断、断点续传；过滤与模型转换批量写。  
- 增量：Canal binlog → MQ → 消费写新库；内存队列合并降写频。

### Q5.3 如何防止增量丢消息导致不一致？（高频深挖）

手动拉取 + 消息记录表 + 多定时任务：拉取落库 → 消费成功改状态 → 再手动提交；用状态机保证「至少一次」下的可追踪，再靠幂等防重复。

**建议白板画：** Old DB → Canal → MQ → Record Table → Consumer → New DB。

## 6. 大搜车 · API 治理与智能测试平台

### Q6.1 扫描百万接口怎么做到？专利点是什么？

- 痛点：多语言、甚至自研 MVC，接口资产收不齐。  
- 措施：自研扫描组件，源码/编译产物 + 语法树/类加载，支持全量/增量；已申请专利并获集团奖励。  
- 价值：治理与测试的基础数据。

### Q6.2 案例执行架构为何「数据集中、执行分布式」？

Meta（接口/案例）集中管理；执行跑在多源算力（平台 + 用户资源），扛住百万级案例规模。

### Q6.3 AI 在测试里做什么？

案例推荐、造数智能体；并用 jacoco 等看覆盖，缓解「全靠测试人员经验」。

## 7. 软通 · 车险核心与增值服务

### Q7.1 车险核心拆分你怎么拆？你的角色？

开发负责人：提拆分方案，参与迁移讨论，协调任务，核心模块设计开发上线。

### Q7.2 新老系统并行如何保证数据可读可写？

### Q7.3 增值服务分布式事务案例

订单与库存拆分；RocketMQ 可靠消息 + 最大努力通知做最终一致；模块抽象为后续渠道/SaaS 预留扩展点。
